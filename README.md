# داشبورد پایش کیت‌های هورمونی (نسخه‌ی «فقط کیت» — بدون هزینه/قیمت)

یک داشبورد تحت وب (Flask) که مستقیماً از روی همان دیتابیس آرشیوشده‌ی
`historical_database_hafez.db` کار می‌کند. **هیچ اطلاعات هزینه، قیمت، درآمد یا
سود در این نسخه محاسبه یا نمایش داده نمی‌شود.**

## سه تب داشبورد

1. **کیت و ظرفیت** — تعداد کیت ورودی/خروجی، ظرفیت کل، موجودی فعلی هر تست.
   با کلیک روی هر ردیف، جزئیات کیت‌ها و تفکیک دستگاه (Cobas/Architect) آن
   تست باز می‌شود.
2. **پارتی‌ها و انقضا** — وضعیت هر پارتی (لات) هر کیت: مانده، تاریخ انقضا،
   وضعیت، و روزهای باقی‌مانده. مرتب‌شده از نزدیک‌ترین انقضا. پارتی‌های با
   کمتر از ۳۰ روز مانده، هایلایت می‌شوند.
3. **علت تکرار تست‌ها** — همان فایل اکسلی که بخش فنی برای ثبت تکرارها تهیه
   می‌کند (ستون‌های تاریخ، شماره پذیرش، تست، علت تکرار، دستگاه‌ها، نتایج و...).
   این فایل را از همین تب آپلود کنید — پس از اولین بار، کنار `app.py` در
   فایلی به نام `repeats_cache.csv` ذخیره می‌شود و لازم نیست دوباره آپلود
   کنید (فقط وقتی فایل جدیدی دارید، دوباره آپلود کنید تا جایگزین قبلی شود).
   داشبورد به‌طور خودکار تعداد تکرار به تفکیک تست، دستگاه نهایی، و علت را
   نمودار می‌کند تا مشخص شود تکرارها الگوی طبیعی دارند یا نه.


   ## تب چهارم — دستیار هوشمند (RAG)

یک چت‌بات که به داده‌ی همین گزارش وصل است. سؤال را به فارسی می‌پرسی،
پاسخ بر پایه‌ی داده‌ی همان بازه و همان بخش تولید می‌شود.

**معماری:**
1. **Retrieval (بازیابی):** گزارش جاری به ~۱۰۰ سند کوتاه و مستقل تبدیل
   می‌شود (هر تست، هر پارتی نزدیک به انقضا، هر علت تکرار و ...). سپس با
   **BM25** (یا TF-IDF اگه BM25 نبود) مرتبط‌ترین اسناد به سؤال پیدا می‌شود.
2. **Generation (تولید):** همان چند سند به یک مدل زبانی محلی و رایگان
   (Ollama) داده می‌شود تا پاسخ فارسی و مبتنی بر داده تولید کند.

**حالت آفلاین:** اگر Ollama نصب/در حال اجرا نباشد، چت‌بات به‌صورت خودکار
به حالت «پاسخ rule-based» می‌رود و اسناد مرتبط را به‌صورت خوانا نشان می‌دهد.
یعنی تب چهارم **همیشه** جواب می‌دهد، حتی بدون هیچ سرویس جانبی.

### اجرای Ollama (اختیاری، برای پاسخ روان‌تر)


## نصب و اجرا

```
pip install -r requirements.txt
python app.py
```
سپس مرورگر را باز کنید: `http://127.0.0.1:5050`

## اجرا روی شبکه‌ی محلی (تا کارفرما هم ببیند)

آخرین خط `app.py`:
```python
if __name__ == '__main__':
    app.run(debug=False, host='0.0.0.0', port=5050)
```
آی‌پی سیستم خودتان را با `ipconfig` پیدا کنید و به کارفرما بدهید:
```
http://<آی‌پی-شما>:5050
```
اگر فایروال مانع شد:
```
netsh advfirewall firewall add rule name="Hormone Dashboard" dir=in action=allow protocol=TCP localport=5050
```

## نکات مهم

- تاریخ‌ها همه **شمسی** هستند (`1405-01-01`).
- «تعداد تست» فقط از تست‌های ثبت‌شده روی دستگاه‌های Cobas و Architect محاسبه
  می‌شود.
- جدول «پارتی‌ها» یک عکس لحظه‌ای از آخرین وضعیت ثبت‌شده در دیتابیس است، نه
  فیلترشده با تاریخ.
- فایل اکسل «علت تکرار» می‌تواند هر تعداد ستون داشته باشد و دقیقاً همان
  ستون‌هایی که در فایل شماست را نمایش می‌دهد — لازم نیست ساختارش با نمونه‌ی
  اولیه یکی باشد، فقط ستون‌های «تاریخ» و «شماره پذیرش» باید وجود داشته باشند
  تا برنامه سطر سرستون را پیدا کند.
- برای تشخیص تاریخ در فایل تکرارها، هم فرمت `1404/01/06` و هم `1404-01-06`
  پشتیبانی می‌شود.
- اگر مسیر اجرای `app.py` عوض شود، مسیر `repeats_cache.csv` هم کنارش
  جابه‌جا می‌شود؛ برای مسیر دلخواه می‌توانید متغیر محیطی `REPEATS_CACHE_PATH`
  را تنظیم کنید.
